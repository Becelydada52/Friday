# Интерфейс локального ИИ-агента (MVP)

## Запуск
```bash
pip install -r requirements.txt
ollama serve            # если ещё не запущен
ollama pull qwen2.5-coder:7b   # или другая модель
python app.py
```

## Что внутри
- **Чат-панель** (слева): отправка сообщений в Ollama (`/api/chat`), потоковый вывод токенов, история диалога хранится в памяти окна.
- **Панель команд** (справа): выполнение shell-команд через `subprocess`, построчный вывод в реальном времени.
- Обе части работают в отдельных `QThread`, UI не блокируется во время генерации/выполнения.

## Осознанные ограничения MVP (сделано намеренно, не баг)
- Нет привязки к конкретному проекту/директории — команды выполняются в cwd процесса.
- Нет истории чатов на диск — при перезапуске история теряется.
- Нет отмены генерации (стоп-кнопки) — worker её поддерживает (`stop()`), кнопку просто ещё не повесили в UI.
- Нет автоматического связывания вывода команд с ответом агента (агент пока не "видит" вывод правой панели).

## Следующий логичный шаг
Как только MVP чата обкатан — следующий приоритет: дать агенту сам вызывать команды
(tool calling), а не только человеку вручную. Тогда правая панель станет логом
инструментов агента, а не отдельным терминалом.
